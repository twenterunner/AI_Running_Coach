WHAT WAS FIXED

1. FEASIBLE LIFECYCLE REPAIR
- The previous repair pass could rebuild graph points while leaving an over-capacity assignment in the ledger.
- Capacity overflow is now repaired chronologically.
- If a session would push a pair beyond its retirement target, that exact session is moved to the highest-scoring serviceable pair.
- If no existing pair has enough remaining capacity, a just-in-time successor is created and used immediately.
- A deterministic fallback lifecycle is built if the first lifecycle still fails hard validation.
- The generic "Shoe lifecycle unavailable" / "Shoe plan temporarily blocked" release state has been removed.
- Truly contradictory constraints can still be reported explicitly rather than silently displaying an invalid graph.

2. ONE SCORE, ONE EXPLANATION
- Headline Shoe Suitability and the visible component scores now come from the SAME shoeSuitabilityAssessment() object.
- Overall score is the weighted average of the displayed components.
- No hidden additive bonus is applied after the visible component calculation.
- A score of 100/100 is forbidden if any positively weighted visible component is below 100.
- Session-specific component weights are shown to the runner.

Visible components:
- Workout match
- Distance match
- Cushioning / protection
- Responsiveness / efficiency
- Stability / support
- Surface / grip
- Foot-mechanics context
- Rehabilitation context when relevant
- Lifecycle / condition

3. FOOTWEAR PLAN VALUE
The Shoes section now shows:
- total remaining training/rehab sessions covered;
- number of physical pairs used;
- planned km and number of sessions per pair;
- dominant session roles per pair;
- next purchase requirement and date, or "None required";
- Race Day pair and projected mileage;
- the next recommendation and score gap versus the next-best shoe;
- a full chronological session-by-session footwear plan;
- every serviceable physical pair's score for every training/rehab session.

4. CROSS-APP SCORE VISIBILITY
- Today shows the recommended physical pair and its score.
- Plan shows the recommended physical pair and its score.
- Rehab shows the proposed physical pair and its score.
- The same comparison foldout is used across these surfaces.
