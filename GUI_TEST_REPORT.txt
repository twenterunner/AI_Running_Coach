AI Running Coach v15.4.8 · build 50408
Whole-app GUI normalization & regression report
Date: 2026-08-22

SCOPE
- Sole baseline: uploaded app.js, index.html, manifest.webmanifest, service-worker.js, styles.css.
- Presentation-only normalization; no calculation/refactor work performed.
- Existing Today / Plan / Log / Progress / Recovery visual direction preserved.

ROOT CAUSES FOUND
1. CSS override debt: 3,471 !important declarations and 103 media-query blocks in the baseline, including many successive version-specific "locked UI contract" patches. This creates selector-specificity conflicts and makes local fixes capable of breaking unrelated screens.
2. Responsive file inputs could participate in layout and widen Settings at all tested widths; Coach also overflowed at 320/360 px in the baseline.
3. Modal rules existed in multiple layers; a single viewport-contained contract was needed so future popup changes do not regress other dialogs.
4. Similar KPI/card/control roles used different spacing/typography rules across modules.
5. Baseline release identifiers were inconsistent: index/manifest/service worker identified v15.4.7 build 50407 while app.js core reported v15.4.5 build 50405.

IMPLEMENTATION
- Added one final authoritative GUI-normalization layer instead of editing historical locked rules throughout the file.
- Added shared design tokens for spacing, card padding/radii, control sizing, typography and touch targets.
- Normalized secondary screen page titles, cards, KPI/mini tiles, controls, disclosures and settings spacing.
- Added one viewport-contained modal/onboarding contract with internal scrolling.
- Added responsive breakpoints for 320, 360, 390, 412, 430 px and wider layouts.
- Removed native file inputs from visual flow while preserving their explicit label-based activation.
- Raised several high-density micro-labels to a more legible minimum without changing information hierarchy.
- Preserved module-specific semantic/chart colours, Shoes retirement markers and Injury phase styling.
- Synchronized version/build/cache references to v15.4.8 build 50408.

VERIFIED LIMITATIONS
1. Normal web navigation to localhost/file URLs is blocked by this execution environment. Browser testing therefore used Chromium set-content injection of the exact HTML/CSS/JS. Layout, rendering and interactions are real Chromium behavior, but service-worker/network cache behavior could not be browser-exercised end-to-end.
2. about:blank browser pages do not expose persistent localStorage. Onboarding and interaction testing therefore ran in-memory. Data-preservation is instead strongly verified by the byte-identical non-version app.js comparison and baseline-vs-release core equivalence tests.
3. The uploaded baseline contains no persisted real user dataset. Empty/default Shoes and Injury states were runtime-rendered; a populated real shoe lifecycle graph and an active multi-phase rehab history could not be reproduced from the supplied files alone. Their calculation/render code is unchanged; shared containment rules were tested structurally.
4. FIT/CSV parsing itself was not re-tested because this release did not alter app.js logic and no representative FIT/CSV fixture was supplied. The import UI/modal path and file-control layout were tested.
