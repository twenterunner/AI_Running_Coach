AI Running Coach v14.4.8 · build 40408

CORRECTIONS

1. COMPLETE RELEASE PACKAGE
The v14.4.7 ZIP was incomplete and did not contain styles.css. That meant a deployment could keep using an older stylesheet even though index.html referenced a new CSS version. v14.4.8 again contains styles.css at the ZIP root and uses a new cache/query identity.

2. MOBILE BOTTOM NAVIGATION
The previous rule intentionally lifted the navigation 28 px above the browser viewport bottom. On the supplied Samsung/Chrome screenshots this left an excessive visible gap. The final mobile rule now uses a 6 px bottom clearance (or the real safe-area inset when larger), 72 px total height and global fixed positioning. The rule applies to the shared #nav element, so it is identical on Today, Plan, Log, Progress, More, Shoes and Settings.

3. RACE DAY PLANNER TRANSACTION
The previous Race Day selector mutated the authoritative pairs/assignments while trialling one late dedicated Race Day shoe. If that trial failed the mileage/familiarisation constraints, the function could return no Race Day pair after having already changed the plan.

v14.4.8 makes this transactional:
- reuse an already race-ready existing pair first;
- otherwise rank current supported race-capable purchase profiles;
- try dedicated Race Day entry weeks from latest to earlier within the familiarisation window;
- force the trial Race Day pair to be part of the selected weekly 2–3-pair portfolio from its first-use week;
- each successful weekly portfolio still gives every used pair >=25% of that week's mileage;
- reject a trial immediately if a week cannot be allocated safely;
- require familiarity, <250 km at race start, race suitability and lifecycle reserve;
- fully rollback pairs, purchases, events and session assignments after every failed trial;
- commit only the first complete feasible Race Day lifecycle.
