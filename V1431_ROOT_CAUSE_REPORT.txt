AI Running Coach v14.3.1 · build 40301
ROOT-CAUSE CORRECTION REPORT

TWO ROOT CAUSES FOUND AND FIXED

1. MOBILE CSS PATCHES WERE MALFORMED
The v14.3.0 mobile navigation and shoe-foldout block contained literal "\n" characters instead of actual
line breaks. Chrome therefore did not reliably parse those rules. This directly explains why the bottom
navigation labels remained clipped and why the shoe-score foldout could still extend beyond the right edge.

v14.3.1:
- final styles.css contains zero literal escaped-newline separators;
- the superseded v14.3.0 mobile block is removed;
- bottom nav uses one authoritative mobile rule:
  fixed bottom:0, height 86 px, button height 62 px, separate icon/label rows, 16 px label line,
  16 px bottom padding, z-index 2147483000, and 118 px content clearance;
- obsolete visualViewport offset JavaScript is removed to avoid double vertical shifting;
- the session shoe foldout is constrained to the card width;
- selected-pair status gets a 112 px column;
- component values get a 76 px column (70 px on <=390 px screens).

2. RACE DAY <250 KM WAS BEING BROKEN AFTER IT HAD BEEN SOLVED
The v14.3.0 engine selected/familiarised a Race Day pair below 250 km and then ran the weekly 25% rebalancer
again. That could add ordinary mileage to the Race Day pair and push it over 250 km. Validation then blocked
the plan instead of preventing the bad allocation.

v14.3.1 stage order:
1. chronological session allocation;
2. weekly 25% balancing;
3. Race Day selection/familiarisation LAST;
4. no ordinary redistribution after Race Day selection;
5. final Race Day hard gate before cache/display.

The final Race Day pair must be below 250 km, satisfy familiarisation, and retain enough lifecycle for the
race plus the safety reserve.
