Release: v14.2.0 · build 40200

ARCHITECTURE
The prior layered shoe lifecycle architecture was removed. The release has one chronological physical-pair planner.

AUTHORITATIVE RULES
1. Existing owned active physical pairs are always considered before a purchase.
2. A new ordinary pair may be created only at the first exact session that no already-available pair can cover appropriately within remaining lifecycle capacity.
3. A future pair starts at 0 km and purchase date = first mileage-producing use.
4. Weekly allocation uses whole sessions and enforces >=25% of weekly running mileage for every rotation-eligible ordinary pair whenever a mathematically feasible assignment exists.
5. Purchases are removed again if the same remaining programme can be covered without them.
6. Race Day first considers owned and already-required training pairs. A dedicated race pair is last resort only.
7. Race Day pair must be <250 km, inside its model-specific familiarity window and retain comfortable lifecycle after the race starts.
8. Rehabilitation uses the same suitability score but is not distorted by ordinary weekly-rotation percentages.
9. Graph mileage is derived only from the final physical-pair assignment ledger. Equal-mileage horizontal usage segments are not drawn.
10. Manual runner overrides remain authoritative unless the physical pair cannot perform the session.
